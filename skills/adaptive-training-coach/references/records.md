# 个人记录与复盘

## 存放与接续

数据与 Skill 包分离。首次用 `scripts/init_data.py --data-dir <私人目录>` 初始化；脚本不会覆盖已有文件。不得将作者或其他使用者数据打包发布。绑定位置写在当前私人工作区的记录中，未来会话优先找已有绑定，避免建第二套档案；跨机器迁移由用户选择私人数据位置。

数据布局：
- profile.md：目标与主次、训练经历、器械/时间、稳定偏好、已确认限制，注明来源与日期。
- program.md：内部阶段策略、观察指标、覆盖/频率、进阶与复盘节点。
- state.md：近期实际训练、当前带日期状态、待确认问题、已计数训练 ID、已复盘覆盖 ID。
- sessions/<training-id>/：plan-v1.json、导出目录及实际反馈 actual.md；修订保存 plan-v2.json 等，不覆盖旧版。
- reviews/：复盘和其覆盖的去重训练 ID、调整依据及下阶段策略。

跨会话读 profile/program/state 和必要最近 3–5 次 actual；历史不足就用已有，不强行补齐。短期疲劳超过数日未确认应视为待核实，不沿用成永久限制。症状持续与否也需核实，不能仅因过期默认消失。

## 事件状态

训练 ID 在计划建立时固定（日期加可区分后缀即可），同一天多次训练用不同 ID。实际日期与计划日期分开；改期沿用该 ID，确为另一训练再新建。

planned → in_progress / completed / partial / cancelled；无反馈保留 planned/未知执行情况。

- 训练中报重量先记录实际，不提前当整次完成。
- 明确“练完了”可记 completed，但未报的动作、次数、重量保留未知，不能复制计划填入 actual。
- 中断记 partial，已做负荷参与下次决策，不计入默认完成计数。
- 修改/补充旧反馈更新同一 ID，不再次计数。
- 取消不计数，纠正完成状态时相应校正 ID 集合，不简单盲加/减计数。
- 计划/实际冲突保留原计划及实际差异；用户明确纠正后标旧事实被纠正。

实际反馈中写已确认结果、未报告字段、症状与疲劳、对下次的影响。稳定能力更新需真实可比表现，不将一次偶然表现或推测永久化。

## 默认小复盘

每 5 个尚未被复盘覆盖的去重 completed ID 触发当次轻复盘；用户可调整间隔或随时主动请求。只有“练完了”但大量内容未知的记录可计完成事件，不能作为负荷进步证据。长期没有完成却持续 partial/cancelled 时，不等满 5 次，主动检查可执行性。

依次比较：执行与时间条件、目标相关表现、可比负荷、恢复/疼痛、重复替换与覆盖。区分缺少证据、执行条件问题、单日异常、处方不合适与阶段策略问题。无稳定证据时保留策略。

复盘记录覆盖 ID 集合，不清空历史计数集合；追加旧数据不重复复盘。说明调整了什么、依据是什么、何时复查。用户目标、长期偏好或重要约束改变时明确向用户核实含义，不能悄悄替用户换目标。

无文件能力时输出包含 profile/program/state/最近实际/计数 ID 的简洁交接记录，提醒下次带入；不可宣称已保存文件、自动云同步或在无消息时持续监控。
